# 【1/3】arai_snow_st：脱Streamlit計画

## 目的

「限られたユーザー（自分含む）が毎朝スマホで3秒で今日の雪を確認できる道具」にする。
判断基準はこの一点。分析機能の充実より起動の速さと一覧性を優先する。

## 現状の課題（なぜStreamlitを出るか）

1. **永続化の不全**：`save_history_data()` のローカルCSV書き込みは、Streamlit Cloudの
   一時ファイルシステムでは再起動のたびに消える。過去月の履歴蓄積はクラウド上で機能していない。
2. **スリープ**：Community Cloudは低頻度アクセスでスリープし、復帰に数十秒。
   少人数×毎朝利用という本アプリの使われ方と最悪の相性。
3. **構造の不一致**：データは1日1回（9時観測）しか更新されないのに、閲覧のたびに
   市サイトへスクレイピングしている。閲覧速度・市サーバーへの負荷・障害検知のすべてで不利。

## 移行後アーキテクチャ

```
GitHub Actions（毎朝 09:30 JST cron）
  └ スクレイピング → data/snow_data.json をコミット（リポジトリ＝DB）
        ↓
静的サイト（GitHub Pages）
  └ index.html + Chart.js が JSON を読んで描画。PWAでホーム画面へ。
```

サーバーなし・コスト0円・コールドスタートなし。

## フェーズ

### Phase 1：データ収集の分離（UI移行より先。既存Streamlit版のまま効果が出る）

- [ ] 既存のスクレイピング＋パース処理（main.pyのtidy化ロジック）を `collect.py` として独立させる
- [ ] GitHub Actions ワークフロー作成：毎朝09:30 JSTに `collect.py` を実行し、
      当シーズン全体を `data/snow_data.json`（表示用・全地点×日次）に整形してコミット
- [ ] 履歴CSVもActionsが更新する形にし、永続化問題を根治
- [ ] `data_urls.csv` の月次手動追記の廃止または自動化：市サイトのインデックスページから
      新月URLを自動発見。発見できない場合のみワークフローを失敗させて通知
- [ ] Streamlit版を「JSONを読むだけ」に改修（スクレイピング処理の呼び出しを削除）
- [ ] 動作確認：ワークフロー失敗時にGitHubから通知メールが届くことを確認

**完了条件**：手を触れずに毎朝JSONが更新され、Streamlit版がそれを表示している。

### Phase 2：静的サイト＋PWA

- [ ] `docs/index.html`（GitHub Pages対象）を新規作成。構成は上から：
      **①数値ファースト**（今朝の積雪cm・前日差・昨日の降雪cmを大きく、全地点分）
      **②シーズン通しグラフ**（11月〜今日。Chart.jsの折れ線、地点切り替え）
      **③月別表示**（既存機能の移植。優先度は低い）
- [ ] スマホ幅（375px）を第一に設計。凡例・軸ラベルの視認性を実機で確認
- [ ] PWA化：manifest.json＋アイコン＋（任意で）Service Workerによる直近データのキャッシュ
- [ ] GitHub Pages 有効化、URLを知人に共有できる状態に

**完了条件**：ホーム画面のアイコンから起動して3秒以内に今朝の数値が見える。

### Phase 3：日常道具としての仕上げ（冬の間に随時）

- [ ] 過去年比較：「去年の同じ日」の積雪を重ね表示（履歴データは7シーズン分の構造が既にある）
- [ ] （任意）朝の通知：Actionsから ntfy.sh 等へ「今朝の積雪128cm(+15)」をプッシュ
- [ ] 知人1〜2名に配布し、感想を1項目だけ聞く：「毎朝見たくなるか」

## スケジュールと締切

- Phase 1〜2 を9月末までに完了、10月は無人稼働の安定確認（Actions成功率の観察）、
  11月の降雪開始時に実用イン。
- 90日計画のW11〜W12に対応。

## リスクと対策

- 市サイトのHTML構造変更 → Actionsが失敗して即メール通知される（現状の「閲覧時に静かに壊れる」より改善）
- JS/TS未経験によるPhase 2の停滞 → Chart.js＋素のHTMLで開始してよい（Next.js必須ではない）。
  フレームワーク練習は方言チャットで行う

## やらないこと

- ユーザー認証・アクセス解析・多機能化。道具の速さを損なう追加はすべて見送る。
