# Claude Code × Streamlit アプリ — できること・できないこと・推奨ワークフロー

## Claude Codeができること

### 1. アプリの起動
```bash
streamlit run main.py --server.headless true
```
をバックグラウンドで実行し、起動ログを監視できる。

### 2. ログ・エラーの検出と修正
- 起動時のエラー（ImportError, SyntaxError等）→ ログから検出 → コード修正 → 再起動
- ランタイムエラー → ログ出力から検出 → 原因特定 → 修正

### 3. コードの静的解析
- VS Codeの診断機能（`getDiagnostics`）でシンタックスエラーや型エラーを検出
- コードを読んでロジックの問題を特定

### 4. 依存関係の確認
- `pip install -r requirements.txt` で依存パッケージをインストール
- バージョン不整合の検出と修正

---

## Claude Codeができないこと / 制約

### 1. ブラウザUIの直接操作はできない
- Claude Codeはブラウザを操作できないため、**画面の見た目や操作結果を直接確認できない**
- ただし、ユーザーがスクリーンショットを提供すれば、画像を解析してUIの問題を特定可能（下記「スクリーンショットの渡し方」参照）

### 2. インタラクティブなデバッグ
- Streamlitのウィジェット操作（サイドバーの選択変更等）を自動で行うことはできない
- ユーザーが操作 → エラー報告 → Claude Codeが修正、というフローになる

### 3. 外部サイトへのアクセステスト
- 外部WebサイトからのスクレイピングやAPI呼び出しが成功するかは、実際にアプリを動かして確認する必要がある

---

## スクリーンショットの渡し方（ターミナルから）

Claude Codeはマルチモーダル対応のため、PNG・JPG等の画像ファイルを視覚的に解析できる。ターミナルから画像を渡す方法は主に2つ:

1. **ファイルパスをメッセージに含める** — 画像ファイルのパスを伝えるだけでOK
   ```
   /Users/apple/Desktop/screenshot.png を見て問題を教えて
   ```

2. **ドラッグ＆ドロップ** — ターミナルに画像ファイルをドラッグ＆ドロップするとパスが入力されるので、そのまま送信

これにより、ブラウザを直接操作できなくても、UIの問題点を特定・修正できる。

## 推奨ワークフロー（2フェーズ）

### フェーズ1: コードレビュー・静的解析（起動前）

1. **依存関係の確認とインストール**
   - `pip install -r requirements.txt` で必要パッケージを確認

2. **VS Code診断でエラー検出**
   - `getDiagnostics` でシンタックスエラーや型エラーを確認

3. **main.pyのコードレビュー**
   - 潜在的なバグ、エラーハンドリングの不備、ロジックの問題を特定
   - データスクレイピング処理の堅牢性を確認
   - Streamlit UIロジックの問題を確認

4. **発見した問題の修正**
   - 問題があればユーザーに報告し、修正を実施

### フェーズ2: 起動・動作確認・デバッグ

5. **Streamlitアプリをバックグラウンドで起動**
   ```bash
   streamlit run main.py --server.headless true
   ```

6. **起動ログの監視**
   - エラーがあれば検出 → 原因特定 → 修正 → 再起動

7. **ユーザーによるブラウザ確認**
   - `http://localhost:8501` をブラウザで開いて動作確認
   - 問題があればスクリーンショットやエラーメッセージを共有してもらい、修正
