## 1. 見つけた問題：3列目の観測所が替わっていた

今季のページの見出しはこうなっていた。

```
観測所 | 新井消防署 | 頸南消防署 | 関山（気象庁観測所）
```

去年までの3列目は「妙高市役所 妙高支所」。**観測所が替わっている。**

収集スクリプトは、列の**位置**で地点名を決めていた（3列目＝妙高支所）。
そのため、関山の値が「妙高支所」という名前で記録される状態だった。
関山はまだ空欄だったので実害は出ていないが、関山に雪が積もった朝から、
**エラーも出ずに別の地点の数字が記録されはじめる**ところだった。

### なぜ気づけたか

市のページを直接開いて、11/22分が載っているか確かめたとき（cronの宿題の確認）。
見出しの文字が目に入った。**自動化しても、元のページを人の目で見る機会は残しておくとよい。**

---

## 2. 直し方

### 2-1. 列と地点は「見出しの名前」で対応づける

見出し行（「観測所」で始まる行）から観測所名を左から読み、名前→地点の対応表
（`STATION_ALIASES`）で引く。**知らない名前が来たら、推測せずに失敗させる。**

- 間違った名前で黙って記録する → 気づくのが何か月も後になる
- 失敗させる → その朝の `status.json` に「知らない観測所名」と残り、すぐ分かる

「止まって知らせる」ほうが、データを守るうえでは親切。

過去の3枚（2010年1月・2016年1月・2025年12月）で、旧方式と**完全に同じ値**が読めることを確認した。

### 2-2. CSVでは区別し、画面ではまとめる

妙高支所も所在地は関山なので、画面では3地点目を「関山」として1本にまとめた。
ただし**CSVには市の表のとおりの名前で残す**（〜2025年度：妙高市役所 妙高支所／2026年度〜：関山）。

計測器が別物（市役所の支所と気象庁の観測所）なので、元データで区別できないと、
あとで「この年から値の傾向が変わったのはなぜ？」となったときに追えなくなる。
**まとめるのは表示の直前（JSONを作る段階）**にした。フッターにも一言添えた。

### 2-3. 古い名前で入ってしまった行の掃除は「月ごと置き換え」で

今季11月分には「妙高支所」名の空行が30行入っていた。
CSVを手で直すと、毎朝の自動コミットと衝突しやすい。

そこで、**取得した月は、その月の行をまるごと新しい内容に置き換える**ようにした。
月ページはその月の全日・全地点を載せた「正」なので、入れ替えて問題ない。
次の朝の実行で、古い行は自動的に消える（dry-runで「30行除去・30行追加」を確認）。

行が大きく減るような取り違えは、もとからある `check_consistency()` が止める。

## 3. 前年度の切り替えボタン

シーズンの始まりはデータが少なく、グラフが寂しい。「去年はどうだったか」も振り返りたい。
検討メモ（plans/2026-10-16_past-season-comparison.md）の **A案（年を切り替えて表示）** を採用した。

- JSONに `previous`（1つ前のシーズンの `series`）を**追加だけ**する
  - 既存のキーは変えない。Service Worker のキャッシュで「古い画面＋新しいJSON」の組み合わせが
    起きても、古い画面は `previous` を無視するだけで壊れない
  - 逆に「新しい画面＋古いJSON」でも、`previous` が無ければ年度ボタンを出さないだけ
- 画面はグラフ部分だけを切り替える。数値パネルは「今朝の雪」のまま動かさない
- 年度と地点は別々に選べる。年度を切り替えても、選んでいた地点はそのまま
- 年度ボタンは地点ボタンより控えめな見た目にして、2段のボタンを見分けやすくした
- Service Worker の `VERSION` を `v3` に上げ、古いキャッシュを捨てさせる

### つまずいた点：CSSは後に書いたほうが勝つ

年度ボタンの「控えめな選択色」が効かず、地点ボタンと同じ塗りつぶしになった。
`.season-tabs button[aria-selected="true"]` と `.tabs button[aria-selected="true"]` は
**同じ強さのセレクタ**なので、ファイルの後ろに書いたほうが勝つ。順番を入れ替えて解決した。

## 5. Streamlit版のテストが7件落ちていた件

今回の変更とは無関係に、main でも9件中7件が落ちていた。原因は2つ。**どちらもアプリではなく、テストとデータの前提のずれ。**

### 5-1. 「最新月」が季節とともに動いた（6件）

テストに `LATEST_MONTH = (2026, 3)` と直書きしてあった。オフシーズンに書いたテストなので、
当時の最新月は3月。11月ページが公開されると、アプリの既定の月は2026年11月に移る。

11月はまだ新井・妙高支所が全日欠測なので、既定の表示はグラフ1件＋案内2件になる。
「グラフが3件出る」前提のテストが連鎖して落ちた。

**直し方：**

- 最新月はテストの中で履歴CSVから求める
- 「グラフが3件」を確かめるテストは、値のそろった過去の月（2025年1月）を明示的に選んで行う
- 既定表示は「グラフ＋案内で3件」と数える（季節の初めに欠測の地点があるのは正常）

**教訓：毎日増えるデータを読むテストに、「今」の値を直書きしない。**
書いた日には正しくても、季節が変わると落ちる。

### 5-2. 市が2009年12月のリンクを一覧から外した（1件）

11/20 の自動コミットで、`data_urls.csv` から `2009,12` が消えて `2026,11` が増えていた（どちらも97件）。
ページ自体はまだ開ける。市のトップの一覧から**リンクだけが外れた**（件数に上限があるのかもしれない）。

Streamlit版は年・月の選択肢を `data_urls.csv` から作っていたため、2009年が選べなくなっていた。
**履歴CSVにはデータが残っているのに選べない**という実害。

**直し方：** 選択肢を履歴CSVから作る。`data_urls.csv` は「市の一覧の写し」で、市の都合で変わる。
「手元にあるデータ」を基準にすれば、市の一覧がどう変わっても選べる。

### 5-3. あわせて：地点を静的サイトとそろえた

Streamlit版の地点も「新井・頸南・関山」の3つにし、妙高支所の行は読み込み時に関山として扱う。
過去の年月で「関山」を選ぶと、妙高支所の値が出る。

マージ後に11月分が「関山」の行に置き換わったCSVでも、9件すべて通ることを確認した。

## 6. マージ後：「今年度」ボタンだけが出て、押しても切り替わらなかった

マージして手動で収集を走らせたあと、スマホで開くと「今年度」ボタンが1つだけ出て、前年度に切り替えられなかった。
公開中のJSONには `previous` が正しく入っていた。**サーバーではなく、スマホ側の問題。** 原因は2つ重なっていた。

### 6-1. `hidden` 属性がCSSに負けていた

前年度が無いときは `seasonTabs.hidden = true` で年度ボタンの列ごと隠すつもりだった。
しかし `hidden` の正体はブラウザ既定の `display: none` で、**自分で書いた `.tabs { display: flex }` のほうが勝つ。**
結果、押しても何も起きないボタンが1つだけ見えていた。

対策：`[hidden] { display: none !important; }` を1行足す。よく知られた落とし穴で、定番の対策。

### 6-2. 前年度の入っていない古いJSONを使っていた

- マージ直後に新しい Service Worker（v3）が入り、その時点のJSON（まだ `previous` が無い）を保存した
- さらに、Service Worker からの `fetch()` もブラウザのHTTPキャッシュを通る。GitHub Pages は最大10分キャッシュさせるので、
  手動実行の直後に開いても古いJSONが返りうる

対策：データの取得に `cache: "no-cache"` を付ける。毎回サーバーに「変わったか」を確かめる（変わっていなければ304で軽い）。
Service Worker の版を v4 に上げた。

### 教訓

「新しい画面＋古いデータ」の組み合わせは検討メモ（5-1）で予想していて、壊れないようにはしてあった。
**壊れはしなかったが、「何も起きないボタン」として見えてしまった。** 隠したつもりのものが本当に隠れているかは、
データが欠けた状態で画面を撮って確かめるべきだった。

## 7. マージ前にPCで確かめる手順を作った（tools/preview.py）

### なぜ必要になったか

6章の不具合は、**マージして本番に出てから**スマホで気づいた。PCのブラウザで開いても同じだった。
GitHub Pages は main の `docs/` しか公開しないので、ブランチの画面を見る手段が無く、
「マージしてから見る」しかなかったのが根本の原因。

### やったこと

ブランチの `docs/` を手元のPCで配信する小さなWebサーバーを作った。

```bash
git switch <ブランチ名>
python3 tools/preview.py        # → http://localhost:8765/ をシークレットウィンドウで開く
```

工夫は3つ。

| 工夫 | 理由 |
|---|---|
| ブラウザのHTTPキャッシュを無効にする（`Cache-Control: no-store`） | 直したファイルが、開き直すたびに確実に届くようにする |
| シークレットウィンドウで開くよう案内する | localhost でも Service Worker が画面を保存する。閉じれば保存分ごと消えるので、古い画面に惑わされない |
| `127.0.0.1` だけで待ち受ける | 同じネットワークの他の機器からは見えないようにする |

localhost は本番（kehorikawa.github.io）とは**別のオリジン**として扱われるので、
ここで何をしても、ふだん使っているアプリのキャッシュには影響しない。

### 使ってみて

PR #12 をマージ前にこの手順で確かめ、前年度ボタンが切り替わることを確認してからマージした。
**「PRを作る → 手元で開いて触る → マージ」**の順番が、これからの基本の流れになる。

### 教訓

自動テストの無い画面の変更は、**マージ前に人の手で触る機会を作っておく**。
ヘッドレスChromeのスクリーンショットでも確かめていたが、それは「正しいデータが来た場合」の絵だった。
実際に人が触ると、キャッシュやデータの欠けといった「本番の条件」に出会える。
